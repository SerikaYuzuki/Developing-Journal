# 大学講義ノートの編集方針

`posts/univ_lecs/` 配下の講義ノートを新規作成・再構成・過去問統合するときの共通ルール。読者が**最初から順に読めば初見の問題にも取り組め、最後に模範解答で答案を確認できる**ことを目標にする。

## 1. 一次資料を起点にする

- PDF、配布資料、板書写真などの**元資料を優先**する。OCRテキストは検索・下書きには使えるが、数式、添字、符号、空欄、単位、表の値は必ず元資料で照合する。
- OCRが壊れた式を推測で確定しない。判読できないときは元PDFを高解像度で確認し、それでも不明なら不明点を残して確認を求める。
- 年度・元の問番号・「統合元」「出題対応」などは、学習用本文では原則として書かない。必要なのは出典の並びではなく、概念のつながりである。
- 同じ概念・導出・計算を問う問題は一つへ統合する。片方にしかない条件、数値例、よい問い方は統合問題へ残す。

## 2. 問題を記事の起点にする

- 記事冒頭に、問題から独立した長い「基礎知識」「理論解説」「講義内容まとめ」を置かない。最小限の目次・記事の使い方を除き、説明はすべて、それを必要とする問題の**理論欄**へ入れる。
- 元資料に問題より先に説明文がある場合も、そのまま前置きとして転載しない。どの問題を解くための知識かを判断し、対応する理論欄へ分配・再構成する。
- 各問題は「まず自力で考える → 分からなければ理論を読む → 模範解答で答案を確認する」という一つの学習単位にする。
- 問題の順番は元の年度順・問番号順に縛られない。後の問題に必要な道具を先に学べるよう、概念の依存関係で並べ替える。

各演習の読む順番は「問題 → 理論 → 解答」とし、次の骨格を使う。

```markdown
#### 問題X1 短く内容が分かる題名

問題文。必要なら資料図・表をここに置く。

::: {.callout-note collapse="true"}
##### 理論X1：なぜこの式・現象になるか

前提、図、導出、直感、典型的な誤り。
:::

::: {.callout-tip collapse="true"}
##### 解答X1

試験答案として必要な仮定、式、結論だけを簡潔に書く。
:::
```

- 問題文は、自力で考えるための入力だけにする。長い説明・導出・解法のヒントは理論欄へ移す。
- 理論欄は、その記事を先頭から読んできた初学者だけを前提にする。未説明の専門語・式・記号を突然使わず、必要なら中学・高校・既修科目の内容まで短く戻って説明する。
- 別の問題で説明済みの内容は、同じ長文を複製せず、「問題Xの理論」で定義した事項として内部リンクで参照する。ただし、その場で必要な結論と適用条件は一文で再掲する。
- 解答欄は理論の要約ではない。問題の問いに直接答え、採点される仮定・式・数値・単位・図・結論を過不足なく置く。

## 3. 理論は「直感 → 厳密さ」の順に説明する

理論欄は、できるだけ次の順に組み立てる。

1. **問いの正体**: この問題は何を見抜ければ解けるのかを、まだ数式を使わず一言で示す。
2. **目に見えるイメージ**: 身近な例、模式図、因果関係を使い、「何が動くか」「何が駆動力か」「何が妨げるか」を説明する。
3. **用語と記号**: 専門語、物理量、正負の向き、軸、単位を定義する。
4. **原理と導出**: 保存則・熱力学・速度論など、どの原理から式が出るのかを途中式つきで示す。式変形だけでなく、各項が現象の何に対応するかを書く。
5. **問題への接続**: 与えられた条件をどの式・図に対応させ、どの順に判断・計算するかを示す。
6. **適用限界と誤りやすい点**: 近似、境界条件、符号、単位、混同しやすい概念を確認する。

- 「なぜそうなるか」と「どのように使うか」の両方を書く。事実や公式だけを列挙しない。
- ファインマン式に、初学者へ口頭で説明できる平易さを目指す。たとえば相変態なら「原子が移りたがる理由」と「移動に時間がかかる理由」を分けてから、自由エネルギーと拡散へ結びつける。
- 直感的な比喩は有効だが、対応する物理量と、比喩が成立しなくなる点も明示する。たとえば電荷中性条件は「キャリヤの出どころ」ではなく、最終状態の正負電荷の帳簿として説明する。
- 説明を書いた後、「この説明だけを読んだ人が、用語を定義し直し、式の由来を説明し、類題へ適用できるか」を基準に不足を補う。

## 4. 概念の順に並べる

- 元資料の年度順・配布順をそのまま採用しない。後の問題を解くのに必要な概念を先に置く。
- 典型的には「観察・定義 → 基本法則 → 導出 → 計算 → 応用・設計」の順にする。
- 複数章をまたぐ連鎖問題は、末尾などに総合問題として置く。前の各節で道具を学び、総合問題で式同士がつながることを確認できるようにする。
- 定数表・公式集は本文の後ろに付録として置く。公式には適用条件・符号・よく混同する量を添える。付録だけを読まないと理論欄を理解できない構成にはしない。

## 5. 図・表・コードの置き場所

- 設問が図を読み取らせるなら、元資料の図を**問題文の直後**に残す。キャプションと `fig-alt` を付ける。
- 説明のための模式図、導出を助けるグラフ、Pythonで再現した図は**理論欄の中**へ置く。問題の答えを先に見せない。
- 模範解答そのものとして図・グラフが要求される場合は、完成図を**解答欄の中**にも置く。理論欄では、その図を自力で描くための軸・境界・形状の決め方を説明する。
- 図は「何を比較し、何を読ませるか」が一目で分かるようにする。軸、単位、凡例、代表値、色以外の区別を必ず確認する。
- 元図の解像度が低い、文字が潰れている、または学習上読みづらい場合は、そのまま拡大して済ませず、次の優先順で見やすい図を用意する。
  1. 教科書・論文・公的資料など、出典と利用条件を確認できる同一データまたは一次資料を探す。
  2. 数値データや理論式が得られるなら、Python・Julia・LaTeX/TikZなどで再作図する。
  3. 数値が不要な概念図なら、元図の意味を保って模式図として描き直す。
- 元データがない図を画像から読み取って再現した場合は、厳密な測定値のように扱わず「元図を参考にした模式的再作図」または「図から読み取った近似値」と明記する。存在しない精度を補間で作らない。
- ウェブ上の図をそのまま転載するより、可能なら根拠となるデータ・式を引用して自作図にする。外部資料を使った場合は本文または参考文献に出典を残す。
- Python図には `label`、`fig-cap`、`fig-alt` を付ける。数値例は問題の条件と同じ値を使い、模式図なら模式図であることを明記する。作図コードも記事内に残し、再現可能にする。

## 6. 数式・記号・単位

- `physics` パッケージを前提とし、積分の微小量は `\dd`、常微分は `\dv`、偏微分は `\pdv` を使う。`\frac{\dd y}{\dd x}` や `\frac{\partial y}{\partial x}` の旧式表記を混在させない。
- 記号を最初に定義し、記事内で意味を変えない。特に密度、濃度、電場、電位、エネルギー、電荷の符号を統一する。
- 数値解答には単位を付ける。計算で使った近似（完全電離、非縮退、低注入、一次元、定常状態など）は答案にも一行で示す。
- 与えられた定数表が丸めによって完全には整合しない場合、どの値を優先して計算したかを明記し、図から過剰な有効数字を読まない。

## 7. 模範解答の書き方

- 解答は、試験時間中に答案用紙へ書くことを想定した簡潔な模範解答にする。講義調の長い説明や補足は理論欄へ戻す。
- 記述問題は、原則として「結論 → 理由・機構 → 必要なら結果」の順で書き、問いで指定された語句や比較対象を落とさない。
- 計算問題は「仮定・使用式 → 代入 → 数値と単位 → 結論」を残す。採点者が追えない暗算や、根拠のない数値だけの回答にしない。
- 作図問題は、軸名・単位・代表点・相境界・増減・漸近挙動など、採点対象になる特徴を図中へ明示する。美しさより、何を表す線かが一意に分かることを優先する。
- 複数の表現が正答になりうる場合でも、一つの答案として読み切れる形にまとめる。別解や詳しい補足は、必要な場合だけ解答末尾へ短く添える。

## 8. 編集時の確認手順

1. 元資料から実際の設問、資料図、表、空欄、定数を抽出する。
2. 重複をまとめ、概念順の見出しと問題の対応を設計する。
3. 冒頭や節の前置きに残った説明を、それを必要とする各問題の理論欄へ移す。
4. 各問題を「問題 → 折りたたみ理論 → 折りたたみ解答」にする。
5. 理論だけを順に読み、初出の用語・記号・前提が説明済みか、式と現象が結びついているかを確認する。
6. 解答だけを順に読み、問いへの結論、必要な式・図、単位が短く揃っているかを確認する。
7. 数式表記、記号、単位、図の参照先を全体検索でそろえる。
8. 対象記事をレンダーする。

```bash
uv run quarto render 'posts/univ_lecs/<学年・科目>/<記事>.qmd'
git diff --check
```

9. 生成HTMLで、見出し順、問題・理論・解答の対応、内部リンク、数式、画像、折りたたみ、デスクトップと狭い画面での横はみ出しを確認する。
10. `docs/` の生成物もソースと一緒にコミットする。このリポジトリでは `docs/` が公開成果物である。

## 9. 完成条件

- 初見の読者が問題文を読んだ後、理論を開けば解答へ到達できる。
- 記事冒頭の独立した予習解説を読まなくても、各問題と対応する理論だけで学習が完結する。
- 理論を閉じた状態でも、問題が自力演習として成立する。
- 解答だけを開けば、試験答案に必要な内容を短時間で復習できる。
- 図を含む問題では、低解像度の元画像に頼らず、必要な情報を判読でき、再作図の根拠と精度が明確である。
- 元資料の誤読・OCR由来の崩れ・重複問題・出典管理用メタ情報が、学習の流れを妨げない。
